Cách dùng website APIUYTIN hiện tại

Phần này mô tả đúng các màn hình đang có trên website APIUYTIN: nơi tạo tài khoản, nơi quản lý project, nơi xem người dùng đã đăng nhập và cách quay lại trang tài liệu. Bạn có thể đọc phần này trước khi bắt đầu tích hợp để biết mỗi nút trên web dùng cho việc gì.

1. Các trang chính và nhiệm vụ của từng trang

2. Tạo và đăng nhập tài khoản APIUYTIN

  1. Nếu chưa có tài khoản, mở trang Đăng ký.

    Nhập tên tài khoản dài 3–32 ký tự, nhập mật khẩu tối thiểu 8 ký tự và nhập lại mật khẩu. Bấm biểu tượng con mắt nếu cần kiểm tra nội dung đang nhập. Khi mật khẩu đang hiện, biểu tượng là mắt mở; bấm lần nữa để ẩn lại.

  2. Chọn cách tạo tài khoản phù hợp.

    Bạn có thể tạo tài khoản APIUYTIN bằng tên tài khoản và mật khẩu. Bạn cũng có thể bấm nút Google để xác thực Google và tạo hoặc cập nhật tài khoản APIUYTIN tương ứng. Google không phải là thông tin đăng nhập mà website tích hợp nhận được.

  3. Đăng nhập bằng tài khoản đã tạo.

    Trang Đăng nhập chấp nhận tên tài khoản hoặc email đã liên kết, không phân biệt chữ hoa và chữ thường, cùng mật khẩu đã đăng ký. Nếu bạn dùng Google, hãy dùng nút Google để đi qua luồng xác thực Google. Sau khi thành công, website tạo phiên dashboard riêng bằng cookie HttpOnly.

  4. Không gửi mật khẩu cho website tích hợp.

    Tên tài khoản và mật khẩu chỉ dùng để xác thực với APIUYTIN. Website bên thứ ba chỉ nhận profile APIUYTIN sau khi người dùng đồng ý trong màn hình OAuth; API key vẫn chỉ dùng ở máy chủ của website tích hợp.

3. Bắt đầu từ Home và tạo project

  1. Mở Home sau khi đăng nhập.

    Thanh bên trái có các khu vực Home, API keys, Người dùng của tôi và Tài khoản. Mục Home là nơi quay về dashboard; mục API keys là nơi làm việc với project.

  2. Vào API keys và bấm tạo project.

    Đặt tên project theo môi trường, ví dụ Website production hoặc Website staging. Nên tách production và staging thành hai project để không dùng nhầm callback hoặc API key.

  3. Nhập callback URL chính xác.

    Callback phải là HTTPS và phải khớp từng ký tự với URL mà máy chủ website tích hợp dùng. Không thêm slash cuối tùy ý, không dùng fragment #, username hoặc password trong callback.

  4. Lưu thông tin trả về ngay sau khi tạo.

    Project trả ra clientId để bắt đầu OAuth và API key dạng văn bản chỉ một lần. Lưu API key vào secret manager phía máy chủ ngay lúc này; nếu đóng hộp thoại hoặc làm mất key, hãy dùng chức năng cấp lại key.

4. Cho website khác đăng nhập bằng APIUYTIN

  1. Website tích hợp bắt đầu tại OAuth.

    Máy chủ website tích hợp tạo state ngẫu nhiên, lưu state vào session của chính website đó rồi chuyển trình duyệt tới /oauth/google bằng Client ID, callback URL và state.

  2. Người dùng nhìn thấy bộ chọn tài khoản APIUYTIN.

    Nếu thiết bị đã ghi nhớ tài khoản, màn hình hiển thị avatar, tên và email để người dùng chọn. Màn hình cũng cho biết project nào đang yêu cầu đăng nhập, callback domain nào sẽ nhận kết quả và các trường hồ sơ sẽ được chia sẻ.

  3. Dùng tài khoản APIUYTIN bằng mật khẩu nếu cần.

    Nếu tài khoản chưa có trên thiết bị, người dùng có thể chọn liên kết Đăng nhập bằng tài khoản APIUYTIN, nhập tên tài khoản hoặc email đã liên kết cùng mật khẩu đã tạo ở trang đăng ký. Sau khi xác thực, tài khoản được liên kết với thiết bị và quay lại màn hình đồng ý.

  4. Dùng Google chỉ khi cần xác thực tài khoản.

    Thiết bị mới, thêm tài khoản mới hoặc tài khoản chưa từng được xác thực sẽ chuyển qua Google. Sau lần xác thực đó, tài khoản APIUYTIN được ghi nhớ trên thiết bị cho những lần chọn sau.

  5. Bấm Tiếp tục để đồng ý hoặc Hủy để dừng.

    Tiếp tục tạo authorization code dùng một lần rồi chuyển về callback. Hủy không tạo token mà trả error=access_denied kèm state để website tích hợp kết thúc đúng phiên đăng nhập.

  6. Website tích hợp đổi code ở máy chủ.

    Máy chủ dùng API key để đổi code tại token endpoint. Trình duyệt của website tích hợp không được nhìn thấy API key, không được tự đổi code và không được lưu API key trong localStorage.

5. Quản lý project đang hoạt động

  • Công tắc hiệu lực: bật project để cho phép OAuth, token, userinfo, project-info và allusers hoạt động; tắt project để khóa tạm thời mà không xóa project.
  • Cấp lại API key: dùng khi key có nguy cơ bị lộ. Key cũ bị vô hiệu hóa ngay, key mới chỉ hiện một lần. Cập nhật secret manager của website tích hợp ngay sau khi cấp lại.
  • Thu hồi project: dùng khi project không còn cần nữa. Project bị vô hiệu hóa ngay; dữ liệu OAuth liên quan có thể được dọn dẹp ở nền, vì vậy không cần chờ màn hình quay mãi.
  • Sửa callback: chỉ cập nhật khi máy chủ tích hợp đã sẵn sàng nhận callback mới. Sau khi sửa, các yêu cầu OAuth tiếp theo phải dùng callback mới.

6. Xem người dùng và cập nhật danh sách

  1. Mở Người dùng của tôi.

    Chọn project trong hộp chọn. Trang gọi endpoint overview tương ứng và hiển thị tên, email, avatar và thời điểm đăng nhập gần nhất của các tài khoản đã dùng project.

  2. Bấm Làm mới khi muốn xem ngay.

    Nút Làm mới tải lại danh sách mà không cần tải lại toàn bộ trang. Trong lúc chờ, nút chuyển sang trạng thái đang cập nhật để tránh gửi nhiều yêu cầu trùng nhau.

  3. Theo dõi bộ đếm tự động.

    Trang tự polling mỗi 60 giây khi tab đang hiển thị. Bộ đếm cho biết còn bao nhiêu giây tới lần cập nhật tiếp theo. Khi chuyển sang tab khác, trang tạm dừng polling để không tạo request nền không cần thiết.

7. Tài liệu, giao diện và các thao tác nhỏ

  • Tải hướng dẫn Markdown: trong phần đầu trang tài liệu, bấm Tải file Markdown để lấy bản hướng dẫn đầy đủ về contract, bảo mật, kiểm thử và vận hành.
  • Sao chép endpoint: các thanh endpoint có nút Sao chép; sau khi sao chép, trang thông báo trạng thái để người dùng bàn phím và trình đọc màn hình cũng biết kết quả.
  • Đổi theme: nút theme đổi giữa giao diện sáng và tối, đồng thời lưu lựa chọn trên thiết bị.
  • Dùng trên điện thoại: thanh bên chuyển thành dock/drawer ở màn hình nhỏ; các thao tác chính vẫn giữ nút đủ lớn và có focus khi dùng bàn phím.

16 bước tích hợp cho người mới bắt đầu

Nếu bạn chưa từng tích hợp đăng nhập OAuth, hãy đọc phần này từ trên xuống dưới. Hãy tưởng tượng APIUYTIN là quầy lễ tân: website của bạn đưa người dùng tới quầy, người dùng chọn tài khoản, quầy đưa lại một tấm vé dùng một lần, rồi máy chủ của bạn đổi tấm vé đó lấy hồ sơ.

Ba điều quan trọng nhất: Client ID cho biết website nào đang xin đăng nhập; API key là bí mật chỉ máy chủ được giữ; state là chiếc vé kiểm tra để biết người quay về đúng là người vừa bấm đăng nhập.
  1. Bước 1 — Tách phần trình duyệt và phần máy chủ.

    Nút “Đăng nhập bằng APIUYTIN” có thể nằm trên trình duyệt, nhưng API key và thao tác đổi code phải nằm trên máy chủ. Trình duyệt chỉ được chuyển hướng sang APIUYTIN; trình duyệt không được nhìn thấy API key.

    Nếu website của bạn chỉ có HTML/CSS/JavaScript tĩnh, hãy thêm một máy chủ nhỏ hoặc một serverless function để xử lý callback và đổi code.

  2. Bước 2 — Đăng nhập bảng điều khiển APIUYTIN.

    Vào trang chủ APIUYTIN và đăng nhập bằng tài khoản chủ sở hữu. Tài khoản này quản lý project, callback, API key và trạng thái bật/tắt.

  3. Bước 3 — Tạo một project cho website.

    Trong tab API keys, bấm tạo project. Đặt tên dễ nhớ, ví dụ “Website bán hàng production” hoặc “App học sinh staging”. Mỗi môi trường nên có project riêng để bạn không dùng nhầm key.

  4. Bước 4 — Đăng ký callback HTTPS.

    Callback là địa chỉ máy chủ nhận người dùng sau khi họ chọn tài khoản. Ví dụ: https://app.example.com/auth/apiuytin/callback. Địa chỉ phải là HTTPS, không có username, password hoặc fragment sau dấu #, và phải khớp chính xác khi gửi yêu cầu đăng nhập.

    Không tự thêm dấu /, không đổi http thành https ở một nơi khác, và không dùng callback của project A cho project B.

  5. Bước 5 — Cất Client ID và API key đúng chỗ.

    Client ID có thể xuất hiện trong URL bắt đầu OAuth. API key thì giống chìa khóa nhà: chỉ đặt trong biến môi trường hoặc secret manager trên máy chủ. Khi tạo project hoặc cấp lại key, key dạng chữ chỉ hiển thị một lần.

  6. Bước 6 — Tạo cấu hình biến môi trường.

    Đặt Client ID, API key và callback vào cấu hình server. Không commit file .env lên Git, không đưa các giá trị này vào JavaScript chạy trên trình duyệt, và không gửi chúng tới Google Analytics.

  7. Bước 7 — Chuẩn bị nơi lưu phiên và state.

    Website cần một session server-side. Trong session đó, lưu một state ngẫu nhiên, thời điểm tạo và trang người dùng muốn quay lại. State nên sống khoảng 10 phút, chỉ dùng một lần, và bị xóa cả khi đăng nhập thành công lẫn khi người dùng bấm hủy.

  8. Bước 8 — Tạo tuyến bắt đầu đăng nhập.

    Khi người dùng bấm nút đăng nhập, máy chủ sinh state rồi tạo URL /oauth/google với đúng ba tham số: client_id, redirect_uri và state. Sau đó máy chủ trả redirect 302 cho trình duyệt.

  9. Bước 9 — Người dùng đi qua bộ chọn tài khoản.

    APIUYTIN kiểm tra project và callback trước. Nếu thiết bị đã ghi nhớ tài khoản, người dùng thấy avatar, tên và email để chọn. Nếu thiết bị mới hoặc người dùng bấm “Thêm tài khoản”, Google chỉ được dùng để xác thực và liên kết tài khoản vào thiết bị.

  10. Bước 10 — Người dùng bấm Tiếp tục hoặc Hủy.

    Tiếp tục tạo authorization code dùng một lần. Hủy không tạo token; APIUYTIN đưa người dùng về callback với error=access_denied và giữ lại state để website biết đúng lần đăng nhập nào đã bị hủy.

  11. Bước 11 — Nhận callback ở máy chủ.

    Callback đọc chuỗi truy vấn. Khi thành công, chuỗi có code và state. Khi hủy hoặc có lỗi, chuỗi có error và có thể có state. Không giả định tham số luôn xuất hiện theo một thứ tự cố định.

  12. Bước 12 — Kiểm tra state trước khi tin code.

    Máy chủ tìm state trong session hiện tại. Nếu không tìm thấy, hết hạn hoặc đã dùng, dừng ngay. Nếu state đúng, xóa nó khỏi session trước khi tiếp tục. Việc này ngăn một người lấy callback của tab khác rồi đăng nhập nhầm tài khoản.

  13. Bước 13 — Đổi code lấy access token.

    Chỉ máy chủ gửi POST tới /api/auth/oauth/token. Body phải có đúng client_id, api_key, code và redirect_uri. Không gửi client_secret; hệ thống sẽ từ chối trường này.

  14. Bước 14 — Tạo phiên đăng nhập riêng của website.

    Sau khi đổi code thành công, đọc hồ sơ trong payload.user, tìm hoặc tạo tài khoản nội bộ của website bằng user.id hoặc user.sub, rồi tạo session riêng. Không dùng Google subject làm ID hiển thị cho người dùng của bạn.

  15. Bước 15 — Gọi userinfo khi cần.

    Nếu cần đọc lại hồ sơ, máy chủ gửi access token dạng Authorization: Bearer ... tới /api/auth/userinfo. Access token sống 3600 giây và hệ thống không có refresh token; khi hết hạn, bắt đầu lại luồng đăng nhập.

  16. Bước 16 — Kiểm thử rồi mới bật cho mọi người.

    Thử đăng nhập thành công, bấm Hủy, dùng callback sai, dùng state sai, phát lại code, mở trên thiết bị mới, thêm tài khoản mới, tắt project rồi thử đăng nhập, bật lại project, cấp lại API key và thu hồi project. Chỉ đưa vào production sau khi tất cả tình huống đều có thông báo rõ ràng.

Nếu chỉ nhớ một câu: trình duyệt chỉ dẫn đường; máy chủ mới giữ bí mật, kiểm tra state và đổi code.

CẤU HÌNH THỰC TẾ

Cấu hình để chạy được ngay

Phần này giải thích từng ô cấu hình bằng ví dụ. Bạn thay giá trị mẫu bằng giá trị của project thật, nhưng giữ nguyên tên biến để code dễ đọc.

1. Các biến môi trường cần có

APIUYTIN_CLIENT_ID=pk_YOUR_PROJECT_CLIENT_ID
APIUYTIN_API_KEY=CHUOTAPI_YOUR_SERVER_ONLY_KEY
APIUYTIN_REDIRECT_URI=https://app.example.com/auth/apiuytin/callback
SESSION_SECRET=mot_chuoi_dai_ngau_nhien_cua_website_ban
  • APIUYTIN_CLIENT_ID: mã nhận diện project, thường bắt đầu bằng pk_. Mã này được gửi trong URL OAuth.
  • APIUYTIN_API_KEY: key bí mật dùng khi đổi code và gọi API dự án. Chỉ đọc ở server-side.
  • APIUYTIN_REDIRECT_URI: phải giống callback đã lưu trong dashboard, từng ký tự một.
  • SESSION_SECRET: bí mật của chính website bạn để ký session và bảo vệ state; không phải API key của APIUYTIN.

2. Nếu đang chạy trên máy tính cá nhân

APIUYTIN chỉ nhận callback HTTPS. http://localhost:3000 không phải callback hợp lệ theo contract hiện tại. Khi phát triển, dùng một URL HTTPS tạm thời từ tunnel như Cloudflare Tunnel hoặc một môi trường preview HTTPS, sau đó đăng ký URL đó trong project.

Khi chuyển sang production, tạo hoặc cập nhật project bằng callback production. Đừng để callback staging và production dùng chung một API key.

3. Kiểm tra cấu hình trước khi viết code

  1. Mở dashboard và kiểm tra project đang có trạng thái active.
  2. So sánh callback trong dashboard với APIUYTIN_REDIRECT_URI.
  3. Kiểm tra secret manager có chứa API key nhưng trình duyệt không có key.
  4. Gọi GET https://apiuytin.pages.dev/api/auth/health để biết dịch vụ còn phản hồi.
  5. Không dán API key vào ô chat, issue công khai, ảnh chụp màn hình hoặc log CI.

01 / CHUẨN BỊ DỰ ÁN

Chuẩn bị dự án và callback

  1. Đăng nhập bảng điều khiển APIUYTIN bằng tài khoản chủ sở hữu.
  2. Tạo dự án với tên dễ nhận biết và callback HTTPS chính xác của ứng dụng, ví dụ https://app.example.com/auth/apiuytin/callback.
  3. Lưu clientId trong cấu hình ứng dụng. Đây là mã định danh công khai, nhưng vẫn nên dùng đúng dự án theo môi trường.
  4. Lưu apiKey trong trình quản lý bí mật phía máy chủ. Phản hồi tạo dự án hiển thị key một lần.
  5. Đảm bảo tuyến callback có thể nhận tham số truy vấn GET code, state hoặc error.

Callback phải là HTTPS và phải khớp dự án đã đăng ký. APIUYTIN chuẩn hóa URL bằng bộ phân tích URL rồi so sánh callback của yêu cầu với giá trị lưu trên dự án. Không thêm fragment, username hoặc password vào URL.

{
  "project": {
    "id": "project-...",
    "name": "Example Web",
    "clientId": "pk_...",
    "redirectUri": "https://app.example.com/auth/apiuytin/callback",
    "createdAt": "2026-11-08T00:00:00.000Z",
    "status": "active",
    "apiKey": "CHUOTAPI_..."
  },
  "warning": "API key chỉ hiển thị một lần."
}
Không mất API key: APIUYTIN không trả lại key trong phiên, danh sách dự án hoặc project-info. Nếu key mất, chủ sở hữu phải cấp lại và cập nhật trình quản lý bí mật.

02 / YÊU CẦU ỦY QUYỀN

Tạo state và chuyển hướng người dùng

Tạo state ngẫu nhiên cho từng lần đăng nhập. Lưu state trong phiên phía máy chủ hoặc kho state có TTL ngắn, gắn với phiên trình duyệt hiện tại và xóa ngay khi callback xử lý xong. Không dùng một state cố định cho nhiều người dùng hoặc nhiều tab.

// Tuyến Express chạy trên máy chủ của website tích hợp.
import { randomBytes } from "node:crypto";

app.get("/login/apiuytin", async (req, res, next) => {
  try {
    const state = randomBytes(32).toString("base64url");
    req.session.apiuytinStates ||= {};
    req.session.apiuytinStates[state] = {
      createdAt: Date.now(),
      returnTo: "/account"
    };

    // Bảo đảm session đã được lưu trước khi rời website.
    await new Promise((resolve, reject) => {
      req.session.save((error) => error ? reject(error) : resolve());
    });

    const loginUrl = new URL("https://apiuytin.pages.dev/oauth/google");
    loginUrl.searchParams.set("client_id", process.env.APIUYTIN_CLIENT_ID);
    loginUrl.searchParams.set(
      "redirect_uri",
      "https://app.example.com/auth/apiuytin/callback"
    );
    loginUrl.searchParams.set("state", state);
    res.redirect(302, loginUrl.toString());
  } catch (error) {
    next(error);
  }
});

Ba tham số truy vấn được gửi tới APIUYTIN:

  • client_id: Client ID của dự án.
  • redirect_uri: callback đã đăng ký, phải là HTTPS.
  • state: nonce do ứng dụng tích hợp sinh và kiểm tra lại ở callback.

Không gửi API key, hồ sơ người dùng, access token hoặc dữ liệu bí mật trong URL OAuth.

03 / BỘ CHỌN TÀI KHOẢN APIUYTIN

Người dùng chọn tài khoản và đồng ý

APIUYTIN xác thực dự án và callback, tạo transaction ngắn hạn, rồi mở bộ chọn trên cùng origin. Bộ chọn hiển thị tên dự án, domain callback, các tài khoản đã liên kết với thiết bị, avatar, tên, email và mô tả dữ liệu sẽ chia sẻ.

  • Thiết bị đã có tài khoản: người dùng chọn một tài khoản rồi bấm Tiếp tục.
  • Thêm tài khoản: Google OAuth chạy để xác thực tài khoản mới, APIUYTIN tạo hoặc cập nhật apiUser, liên kết tài khoản với thiết bị và quay lại màn hình đồng ý.
  • Thiết bị mới hoặc cookie hết hạn: cần xác thực Google để liên kết tài khoản với thiết bị đó.
  • Hủy: APIUYTIN redirect về callback với error=access_denied và state ban đầu nếu state đã được gửi.

Cookie thiết bị tên apiuytin_device, có thuộc tính HttpOnly, Secure, SameSite=Lax và thời hạn tối đa 30 ngày. Cookie này chỉ giúp APIUYTIN nhớ tài khoản trên thiết bị; website tích hợp không đọc cookie này.

Bộ chọn tài khoản không gửi Google access token hoặc refresh token cho ứng dụng tích hợp. Hồ sơ trả về dùng ID riêng của APIUYTIN.

04 / CALLBACK

Kiểm tra callback trước khi đổi code

Callback nhận một trong hai dạng sau. Thứ tự tham số truy vấn không được xem là cố định.

https://app.example.com/auth/apiuytin/callback?code=ONE_TIME_CODE&state=STATE_CREATED_BY_YOUR_APP
https://app.example.com/auth/apiuytin/callback?error=access_denied&state=STATE_CREATED_BY_YOUR_APP
  1. Đọc state, code và error từ chuỗi truy vấn.
  2. Tìm state trong phiên phía máy chủ của trình duyệt hiện tại; từ chối nếu thiếu, không khớp hoặc đã hết hạn. TTL cục bộ nên ngắn, ví dụ 10 phút.
  3. Xóa state khỏi state store theo cách dùng một lần, kể cả khi người dùng hủy.
  4. Nếu có lỗi error, không gọi endpoint token. Hiển thị thông báo phù hợp; access_denied là thao tác hủy của người dùng.
  5. Nếu không có code hoặc state hợp lệ, dừng xử lý và không tạo session đăng nhập.
  6. Chỉ tiếp tục đổi code ở máy chủ. Không đổi code trực tiếp trong trình duyệt.
Không tin returnTo từ query string để chuyển hướng trực tiếp. Lưu đường dẫn nội bộ trong phiên lúc bắt đầu đăng nhập và chỉ cho phép đường dẫn cục bộ đã kiểm tra.

Mẫu xử lý callback ở máy chủ

Đoạn dưới đây minh họa thứ tự xử lý. Tên hàm lưu session có thể khác tùy framework, nhưng thứ tự kiểm tra thì không nên đổi: đọc lỗi, kiểm tra state, xóa state, rồi mới đổi code.

app.get("/auth/apiuytin/callback", async (req, res, next) => {
  try {
    const { code, state, error } = req.query;
    const saved = req.session.apiuytinStates?.[state];

    // State không có trong session nghĩa là callback lạ hoặc đã dùng.
    if (!state || !saved || Date.now() - saved.createdAt > 10 * 60 * 1000) {
      return res.status(400).send("Phiên đăng nhập không hợp lệ hoặc đã hết hạn.");
    }

    // Xóa trước khi gọi mạng để một lần callback chỉ được dùng một lần.
    delete req.session.apiuytinStates[state];
    await saveSession(req);

    if (error) {
      if (error === "access_denied") return res.redirect("/login?cancelled=1");
      return res.status(400).send("Đăng nhập chưa hoàn tất. Hãy thử lại từ nút đăng nhập.");
    }
    if (typeof code !== "string" || !code) {
      return res.status(400).send("Callback không có authorization code.");
    }

    // Chỉ máy chủ được thực hiện bước này vì body có API key.
    const token = await exchangeApiuytinCode(code);
    req.session.user = await findOrCreateLocalUser(token.user);
    await saveSession(req);
    return res.redirect(saved.returnTo || "/account");
  } catch (error) {
    return next(error);
  }
});

Trong ví dụ này, saveSession, exchangeApiuytinCode và findOrCreateLocalUser là hàm của website tích hợp. APIUYTIN không cung cấp các hàm này; bạn viết chúng theo thư viện session và database của mình.

05 / ĐỔI TOKEN

Máy chủ đổi authorization code

Code có thời hạn tối đa 5 phút, ràng buộc với dự án và redirect URI, và chỉ đổi thành công một lần. Gửi JSON đến endpoint token bằng HTTPS. API key đọc từ biến môi trường hoặc trình quản lý bí mật ở máy chủ.

const tokenResponse = await fetch(
  "https://apiuytin.pages.dev/api/auth/oauth/token",
  {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify({
      client_id: process.env.APIUYTIN_CLIENT_ID,
      api_key: process.env.APIUYTIN_API_KEY,
      code,
      redirect_uri: "https://app.example.com/auth/apiuytin/callback"
    }),
    signal: AbortSignal.timeout(8000)
  }
);

const payload = await tokenResponse.json();
if (!tokenResponse.ok) {
  // Map payload.error; không log request body hoặc api_key.
  throw new Error("Đổi token APIUYTIN không thành công: " + payload.error);
}

const apiuytinUser = payload.user;

Nội dung yêu cầu bắt buộc có đúng các giá trị cần thiết sau. client_secret không được hỗ trợ và yêu cầu có trường này sẽ bị từ chối.

{
  "client_id": "pk_YOUR_CLIENT_ID",
  "api_key": "CHUOTAPI_SERVER_SIDE_KEY",
  "code": "ONE_TIME_CODE",
  "redirect_uri": "https://app.example.com/auth/apiuytin/callback"
}

Response thành công có dạng:

{
  "access_token": "SIGNED_ACCESS_TOKEN",
  "token_type": "Bearer",
  "expires_in": 3600,
  "user": {
    "id": "user-apiuytin-...",
    "sub": "user-apiuytin-...",
    "email": "user@example.com",
    "name": "User Name",
    "picture": "https://example.com/avatar.jpg",
    "given_name": "User",
    "family_name": "Name",
    "locale": "vi",
    "verified_email": true
  }
}

Tạo phiên đăng nhập riêng của website từ hồ sơ đã nhận. Nếu website cần gọi userinfo sau này, chỉ lưu access token ở máy chủ; token hết hạn sau 3600 giây và không có luồng refresh-token trong quy ước này.

Nếu yêu cầu đổi code hết thời gian chờ sau khi gửi, kết quả có thể chưa rõ vì code dùng một lần. Không tự động thử lại cùng code. Kiểm tra trạng thái nghiệp vụ; nếu không thể xác định, bắt đầu luồng đăng nhập mới.

06 / HỒ SƠ

Đọc hồ sơ bằng userinfo

Phản hồi token có hồ sơ trong user. Khi cần xác nhận hồ sơ theo access token hiện tại, máy chủ có thể gọi:

const response = await fetch(
  "https://apiuytin.pages.dev/api/auth/userinfo",
  {
    headers: { authorization: "Bearer " + accessToken },
    signal: AbortSignal.timeout(8000)
  }
);

if (!response.ok) {
  // 401: token không hợp lệ/hết hạn hoặc dự án đã bị thu hồi.
}
const user = await response.json();

/userinfo trả trực tiếp đối tượng hồ sơ, cùng schema với tokenResponse.user:

{
  "id": "user-apiuytin-...",
  "sub": "user-apiuytin-...",
  "email": "user@example.com",
  "name": "User Name",
  "picture": "https://example.com/avatar.jpg",
  "given_name": "User",
  "family_name": "Name",
  "locale": "vi",
  "verified_email": true
}

id và sub là định danh ổn định của APIUYTIN. Subject Google không được gửi cho website tích hợp. Nếu Google không cung cấp trường tùy chọn, trường tương ứng là chuỗi rỗng; verified_email là giá trị đúng/sai.

07 / QUẢN LÝ DỰ ÁN

Quản lý dự án và API key

Các endpoint quản lý dự án yêu cầu phiên chủ sở hữu APIUYTIN, thường do bảng điều khiển cấp qua cookie HttpOnly apiuytin_session. Chúng không phải endpoint đăng nhập người dùng cuối. Từ bảng điều khiển, các yêu cầu cùng origin tự gửi cookie; nếu tích hợp bảng điều khiển khác origin, cần gửi thông tin xác thực và cấu hình phiên phù hợp.

Tạo dự án

POST /api/auth/projects
Content-Type: application/json
Cookie: apiuytin_session=...

{
  "name": "Example Web",
  "redirectUri": "https://app.example.com/auth/apiuytin/callback"
}

Thành công trả HTTP 201. Chỉ phản hồi tạo dự án có API key dạng văn bản gốc lần đầu. Lưu key ngay vào trình quản lý bí mật.

Cập nhật callback

PATCH /api/auth/projects/PROJECT_ID
Content-Type: application/json
Cookie: apiuytin_session=...

{ "redirectUri": "https://app.example.com/auth/apiuytin/callback" }

Giá trị callback mới áp dụng ngay cho yêu cầu OAuth kế tiếp. Đồng bộ cấu hình bên tích hợp trước khi chuyển lưu lượng sang callback mới.

Bật hoặc tắt hiệu lực project

Công tắc trong tab API keys gọi cùng endpoint PATCH nhưng gửi trường enabled. Tắt project không xóa project, không đổi Client ID và không đổi API key; nó chỉ làm project tạm thời không được dùng để đăng nhập hoặc gọi API.

PATCH /api/auth/projects/PROJECT_ID
Content-Type: application/json
Cookie: apiuytin_session=...

{ "enabled": false }

Khi muốn bật lại, gửi { "enabled": true }. Trạng thái trả về là disabled hoặc active. Khi project đang disabled:

  • OAuth mới: /oauth/google từ chối project, nên website tích hợp không thể mở bộ chọn tài khoản cho project đó.
  • Đổi code: /api/auth/oauth/token trả invalid_client, kể cả khi Client ID và API key đúng.
  • API dự án: /project-info và /allusers không chấp nhận API key của project tắt.
  • Access token cũ: /userinfo cũng từ chối vì project không còn active. Website nên yêu cầu đăng nhập lại sau khi project được bật.
  • Quản trị: project vẫn xuất hiện trong danh sách của chủ sở hữu để có thể bật lại. Chỉ revoke mới là thao tác thu hồi và dọn dữ liệu.
Dùng tắt project khi bảo trì hoặc cần khóa tạm thời. Nếu mất API key hoặc nghi ngờ key bị lộ, hãy cấp lại key; tắt project không thay thế cho rotate key.

Cấp lại key

POST /api/auth/projects/PROJECT_ID/rotate-key
Cookie: apiuytin_session=...

Chỉ chủ sở hữu mới được cấp lại key. APIUYTIN thay hash bằng cơ chế bảo vệ phiên bản; key mới trả một lần trong project.apiKey. Sau khi cấp lại thành công, cập nhật trình quản lý bí mật và khởi động lại/tải lại các dịch vụ dùng key. Không có cách lấy lại key cũ dạng văn bản gốc. Nếu hai lần cấp lại chạy đồng thời, yêu cầu thua phiên bản trả key_rotation_conflict; đọc lại dự án và dùng key hiện tại đã lưu an toàn.

Thu hồi dự án

POST /api/auth/projects/PROJECT_ID/revoke
Cookie: apiuytin_session=...

Endpoint đổi trạng thái dự án sang revoked trước, làm token/userinfo/API dự án từ chối sử dụng dự án. Dọn auth code, ánh xạ người dùng và giao dịch OAuth chạy nền khi runtime hỗ trợ waitUntil. Phản hồi có cleanupScheduled; hiệu lực thu hồi được xác nhận bởi trạng thái revoked, không bởi việc dọn dữ liệu đã hoàn tất.

POST/api/auth/projects/:id/revokeChủ sở hữu thu hồi dự án, dọn dữ liệu nền
GET/api/auth/project-infoBearer API key, thông tin dự án không có key
GET/api/auth/allusersBearer API key, người dùng đã đăng nhập vào dự án
POST/api/auth/logoutXóa cookie phiên bảng điều khiển

project-info và allusers dùng API key dưới dạng Bearer. userinfo dùng access token của người dùng cuối dưới dạng Bearer. Hai loại token có mục đích khác nhau, không dùng thay thế nhau.

  • Không retry lỗi 4xx mà không đổi input hoặc trạng thái.
  • Không thử lại mù POST token bằng cùng code sau khi hết thời gian chờ; authorization code là code dùng một lần.
  • Không thử lại thao tác tạo mới, cấp lại hoặc thu hồi vô hạn. Nếu kết quả không rõ, truy vấn trạng thái phù hợp rồi quyết định bước tiếp theo.
  • APIUYTIN thử lại truy vấn Sanity tạm thời với giới hạn; mutation không được thử lại mù. Batch dọn dữ liệu dùng tối đa 50 mutation và đồng thời tối đa 6 tác vụ.
  • Giới hạn đồng thời giảm fan-out nhưng không loại bỏ quota/giới hạn tần suất của Google, Sanity hoặc Cloudflare.

10 / BẢO MẬT

Ranh giới bảo mật

  • Đổi code và mọi yêu cầu mang API key chỉ chạy ở máy chủ.
  • Không đặt API key trong JavaScript trình duyệt, HTML, URL, localStorage, gói ứng dụng di động, analytics hoặc log.
  • Không ghi authorization header, callback code, access token, cookie hoặc token request body vào log.
  • Kiểm tra state phía máy chủ và xóa state sau một lần xử lý.
  • Giới hạn return path về đường dẫn nội bộ để tránh open redirect.
  • Đặt thời gian chờ cho yêu cầu HTTP và giới hạn kích thước nội dung.
  • Chỉ lưu các trường hồ sơ cần thiết. Bảo vệ dữ liệu email và avatar theo chính sách riêng của ứng dụng.
  • Gắn HTTPS cho callback ở mọi môi trường được đăng ký.
  • Không cố tạo luồng vô hạn để né rate limit của upstream.

11 / KIỂM TRA TRƯỚC KHI CHẠY

Kiểm tra trước khi bật đăng nhập

  1. Client ID và API key thuộc đúng dự án/môi trường.
  2. API key chỉ tồn tại trong trình quản lý bí mật phía máy chủ.
  3. Callback HTTPS khớp chính xác dự án đã đăng ký.
  4. State được sinh ngẫu nhiên, lưu phía máy chủ, có TTL và dùng một lần.
  5. Đường đi hủy xử lý access_denied mà không gọi token endpoint.
  6. Đổi token gửi đúng bốn trường: client_id, api_key, code, redirect_uri.
  7. Máy chủ từ chối invalid_client/invalid_grant và không tự tạo phiên khi phản hồi token lỗi.
  8. Ứng dụng tạo phiên cục bộ từ hồ sơ APIUYTIN, không dùng Google subject làm ID người dùng.
  9. Nhật ký đã che code, API key, access token, cookie và authorization header.
  10. Đã thử tài khoản đã nhớ, thiết bị mới, thêm tài khoản, hủy, callback sai và phát lại code.
  11. Đã thử cấp lại key và xác nhận key cũ bị từ chối.
  12. Đã thử tắt project và xác nhận OAuth, token, userinfo, project-info, allusers đều bị từ chối.
  13. Đã bật lại project và xác nhận Client ID/API key cũ dùng lại được bình thường.
  14. Đã xác nhận thu hồi dự án làm userinfo và API dự án bị từ chối.
